A FOUNDATION OF MODERN COMPUTING

The future
started here.
Now follow it back.

In 1971, at Bell Laboratories, First Edition UNIX brought processes, a hierarchical file system and multiple users to the PDP-11/20—in assembly, on a remarkably small machine.

UNIX began on the PDP-7 in 1969. Ken Thompson, Dennis Ritchie and their Bell Labs colleagues were developing ideas that would outlive the hardware: simple mechanisms, consistent interfaces and systems people could understand.

That lineage helped shape Linux, macOS, servers and the infrastructure we now take for granted. Part of the reason we can build what we build today is that someone laid these foundations then.

PRESERVATION WITHOUT A CLAIM OF AUTHORSHIP

We did not write UNIX.
We built new ways to explore it.

This project builds on a historical restoration of Unix V1 around 1972, not an untouched original 1971 disk image. Its reconstruction combines a kernel printout from shortly after V1 with recovered early userland. The restorers' work makes this experience possible.

AN OPERATING SYSTEM DOES NOT LIVE IN RAM ALONE

Do not rewind a video.
Restore the machine.

The next instruction depends on more than registers and memory. Pending IRQs, console FIFO contents, WAIT, poll scheduling, recorded input and the disk blocks just written all matter. Bemu's temporal engine captures the implemented machine and private media state, then reconstructs history through replay.

CHECKPOINT

Keep a complete boundary.

Snapshots are taken between scheduling cycles, not in the middle of an instruction or synchronous DMA operation.

REPLAY

Use the recorded history.

Historical navigation does not mix new keyboard input into the past. Continuing replays retained history before rejoining live capture.

PRIVATE MEDIA

Leave the bases alone.

Temporal modes open regular base images read-only and run against private versions. Restoring a checkpoint restores those versions too.

The matching values are actual FNV witnesses from this captured session. They detect accidental corruption/divergence, not cryptographic authenticity or formal trace equivalence. The footer is a separate capture-driver assertion. The temporal contract defines exact counters, phases, capacities and verification rules.

A NEW SHELL. INSIDE THE OLD UNIX.

Useful ideas.
Historical constraints.

Jash/11 executes as a native PDP-11 program inside the restored kernel, using the V1 fork/exec/wait ABI. Not a host interpreter. Not a replacement for the historical shell.

Quoting and redirection

Literal arguments, input/output files, append, scripts and source.

Session usability

Bounded history, explicit recall, completion lookup and controlled console colors.

An 8 KiB budget

Initialized code/data fits inside its enforced budget in the historical 16 KiB user window.

This is an independently implemented V1 edition, not modern Jash feature parity or POSIX shell certification. No native pipes, job control or expansion are promised. The Jash/11 guide documents the actual commands and bounds.

git clone --recurse-submodules https://github.com/fermihart/unix-v1.git
cd unix-v1
make run-bemu-time

# At the host monitor:

snap
step 10
back 10
regs
continue

Select the assembler with BASM=/absolute/path/to/basm if necessary. Ordinary build/install targets can replace generated working images; back them up before using those workflows. The temporal runtime never writes its supplied bases.

THE LIMITS BELONG IN THE STORY

Preserve the past.
Do not invent the evidence.

This is a supported reconstructed Unix V1 profile, not complete PDP-11 ISA/peripheral compatibility or physical-hardware qualification. Bemu does not implement TC11/paper-tape transfers or DC11 network sessions. Temporal v1 has no alternate-input branches, persistent checkpoint IDs, post-HALT monitoring, base writeback or arbitrary crash recovery.

Recordings contain sensitive guest state and finalize on clean exit. Owner-only mode is not encryption. Navigation cannot retract bytes already displayed on the host terminal or undo arbitrary host effects. The graphics are source-derived presentation, not hardware attestation.
